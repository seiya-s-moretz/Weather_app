# 詳細設計書（天気アプリ）

## 1. コンポーネント構成

本アプリは以下の9コンポーネントで構成する。

- `WeatherContainer`（ViewModelとUIの橋渡しレイヤー）
- `WeatherScreen`（画面全体のUI）
- `SearchArea`（入力欄 + 検索ボタン）
- `WeatherCard`（天気情報カード）
- `ErrorView`（エラー表示）
- `WeatherViewModel`（状態管理）
- `WeatherRepository`（APIを抽象化）
- `WeatherApiService`（Retrofitインターフェース）
- `RetrofitClient`（Retrofitシングルトン）

### 2.1 WeatherContainer

#### 役割（責務）
- `WeatherViewModel` を取得する
- `uiState` を collectAsState() で購読する
- ViewModel のイベントを WeatherScreen に橋渡しする

#### 入出力（I/O）
| 種類 | 内容 |
|------|------|
| 入力 | なし |
| 出力 | WeatherScreen に状態・イベントを渡す |

#### 疑似コード
```kotlin
@Composable
fun WeatherContainer() {
    val context = LocalContext.current
    val repository = WeatherRepository(RetrofitClient.apiService)
    val viewModel: WeatherViewModel = viewModel(
        factory = WeatherViewModel.factory(repository)
    )
    val uiState by viewModel.uiState.collectAsState()

    WeatherScreen(
        uiState = uiState,
        onQueryChange = viewModel::updateQuery,
        onSearchClick = viewModel::fetchWeather
    )
}
```

fun WeatherScreen(
    uiState: WeatherUiState,
    onQueryChange: (String) -> Unit,
    onSearchClick: () -> Unit
) {
    Scaffold(
        topBar = {
            CenterAlignedTopAppBar(title = { Text("天気アプリ") })
        }
    ) { padding ->
        Column(
            modifier = Modifier
                .padding(padding)
                .padding(16.dp)
                .fillMaxSize(),
            horizontalAlignment = Alignment.CenterHorizontally
        ) {

                query = uiState.query,
                isLoading = uiState.isLoading,

                uiState.weather != null -> WeatherCard(weather = uiState.weather)
                uiState.errorMessage != null -> ErrorView(message = uiState.errorMessage)
            }
        }

## 3. ViewModel 詳細

---

### 3.1 WeatherViewModel

#### 役割（責務）
- UiState を保持・更新する
- Repository を呼び出して天気情報を取得する
- エラーハンドリングを行い、エラー種別に応じたメッセージを UiState に反映する

#### UiState

```kotlin
data class WeatherUiState(
    val query: String = "",
    val isLoading: Boolean = false,
    val weather: WeatherUiModel? = null,
    val errorMessage: String? = null
)
```

#### 内部状態
| 状態名 | 型 | 説明 |
|--------|----|------|
| _uiState | MutableStateFlow\<WeatherUiState\> | 内部状態 |
| uiState | StateFlow\<WeatherUiState\> | UIに公開する状態 |

#### 提供するイベント
| メソッド名 | 引数 | 説明 |
|------------|------|------|
| updateQuery | newQuery: String | 入力中の都市名を更新する |
| fetchWeather | なし | 天気情報を取得する |

#### 疑似コード
```kotlin
class WeatherViewModel(
    private val repository: WeatherRepository
) : ViewModel() {

    private val _uiState = MutableStateFlow(WeatherUiState())
    val uiState: StateFlow<WeatherUiState> = _uiState

    fun updateQuery(newQuery: String) {
        _uiState.update { it.copy(query = newQuery) }
    }

    fun fetchWeather() {
        val query = _uiState.value.query
        if (query.isBlank()) return

        viewModelScope.launch {
            _uiState.update {
                it.copy(isLoading = true, weather = null, errorMessage = null)
            }
            when (val result = repository.getWeather(query)) {
                is WeatherResult.Success -> {
                    _uiState.update {
                        it.copy(isLoading = false, weather = result.data)
                    }
                }
                is WeatherResult.Error -> {
                    _uiState.update {
                        it.copy(isLoading = false, errorMessage = result.message)
                    }
                }
            }
        }
    }

    companion object {
        fun factory(repository: WeatherRepository): ViewModelProvider.Factory {
            return object : ViewModelProvider.Factory {
                override fun <T : ViewModel> create(modelClass: Class<T>): T {
                    @Suppress("UNCHECKED_CAST")
                    return WeatherViewModel(repository) as T
                }
            }
        }
    }
}
```

## 4. Repository 詳細

---

### 4.1 WeatherRepository

#### 役割（責務）
- WeatherApiService を抽象化し、ViewModel にデータ操作のインターフェースを提供する
- API通信の成功・失敗を `WeatherResult` に変換して返す
- 例外をキャッチしてエラーメッセージに変換する（ViewModel にエラー処理を漏らさない）

#### 提供するメソッド
| メソッド名 | 戻り値 | 説明 |
|------------|--------|------|
| getWeather(city: String) | WeatherResult | 都市名で天気を取得する |

#### エラーハンドリング詳細
| 例外クラス | エラーメッセージ |
|---|---|
| HttpException（code=404） | 「都市が見つかりませんでした」 |
| HttpException（その他） | 「サーバーエラーが発生しました」 |
| IOException | 「ネットワークに接続できません」 |
| SocketTimeoutException | 「通信がタイムアウトしました」 |
| Exception | 「エラーが発生しました」 |

#### 疑似コード
```kotlin
class WeatherRepository(
    private val apiService: WeatherApiService
) {
    suspend fun getWeather(city: String): WeatherResult {
        return try {
            val response = apiService.getWeather(
                city = city,
                apiKey = BuildConfig.WEATHER_API_KEY,
                units = "metric",
                lang = "ja"
            )
            WeatherResult.Success(response.toUiModel())
        } catch (e: HttpException) {
            val message = when (e.code()) {
                404 -> "都市が見つかりませんでした"
                else -> "サーバーエラーが発生しました"
            }
            WeatherResult.Error(message)
        } catch (e: IOException) {
            WeatherResult.Error("ネットワークに接続できません")
        } catch (e: SocketTimeoutException) {
            WeatherResult.Error("通信がタイムアウトしました")
        } catch (e: Exception) {
            WeatherResult.Error("エラーが発生しました")
        }
    }
}
```

#### 疑似コード
```kotlin
object RetrofitClient {

    private const val BASE_URL = "https://api.openweathermap.org/"

    private val okHttpClient = OkHttpClient.Builder()
        .connectTimeout(10, TimeUnit.SECONDS)
        .readTimeout(10, TimeUnit.SECONDS)
        .build()

    private val retrofit = Retrofit.Builder()
        .baseUrl(BASE_URL)
        .client(okHttpClient)
        .addConverterFactory(GsonConverterFactory.create())
        .build()

    val apiService: WeatherApiService = retrofit.create(WeatherApiService::class.java)
}
```

### 5.3 WeatherResponse（APIレスポンスモデル）

#### 役割（責務）
- API レスポンスの JSON を Gson でパースするデータクラス
- `toUiModel()` 拡張関数で WeatherUiModel に変換する

#### 疑似コード
```kotlin
data class WeatherResponse(
    val name: String,
    val weather: List<Weather>,
    val main: Main,
    val wind: Wind
)

data class Weather(
    val description: String,
    val icon: String
)

data class Main(
    val temp: Double,
    @SerializedName("feels_like") val feelsLike: Double,
    val humidity: Int
)

data class Wind(
    val speed: Double
)

// WeatherResponse → WeatherUiModel への変換
fun WeatherResponse.toUiModel(): WeatherUiModel {
    return WeatherUiModel(
        cityName = name,
        description = weather.firstOrNull()?.description ?: "",
        iconUrl = "https://openweathermap.org/img/wn/${weather.firstOrNull()?.icon}@2x.png",
        temperature = main.temp,
        feelsLike = main.feelsLike,
        humidity = main.humidity,
        windSpeed = wind.speed
    )
}
```

### 5.4 WeatherUiModel（UI表示用モデル）

#### 役割（責務）
- UI層で天気情報を表示するためのデータクラス
- `WeatherResponse`（APIレスポンス）とUIを切り離すための中間モデル
- APIの変更があっても `toUiModel()` だけ修正すればUIに影響しない

#### フィールド一覧
| フィールド名 | 型 | 説明 |
|---|---|---|
| cityName | String | 都市名 |
| description | String | 天気の説明（例：「晴れ」「曇り」） |
| iconUrl | String | 天気アイコンのURL |
| temperature | Double | 気温（℃） |
| feelsLike | Double | 体感温度（℃） |
| humidity | Int | 湿度（%） |
| windSpeed | Double | 風速（m/s） |

#### 疑似コード
```kotlin
data class WeatherUiModel(
    val cityName: String,
    val description: String,
    val iconUrl: String,
    val temperature: Double,
    val feelsLike: Double,
    val humidity: Int,
    val windSpeed: Double
)
```

### 5.5 WeatherResult（sealed class）

#### 役割（責務）

## 6. データフロー（詳細）

### 6.1 天気取得フロー（成功）

```
ユーザーが都市名を入力 → 検索ボタンタップ
    ↓
WeatherViewModel.fetchWeather()
    ↓ isLoading = true
WeatherRepository.getWeather("Tokyo")
    ↓ suspend fun
WeatherApiService.getWeather(...)
    ↓ HTTP GET
OpenWeatherMap API
    ↓ WeatherResponse（JSON）
WeatherResponse.toUiModel()
    ↓ WeatherUiModel
WeatherResult.Success(data)
    ↓
_uiState.update { weather = data, isLoading = false }
    ↓
WeatherContainer.collectAsState()
    ↓
WeatherScreen → WeatherCard 表示
```

### 6.2 天気取得フロー（失敗）

```
WeatherApiService.getWeather(...) → 例外発生
    ↓
WeatherRepository が catch
    ↓ 例外の種別に応じてメッセージを決定
WeatherResult.Error("都市が見つかりませんでした")
    ↓
_uiState.update { errorMessage = "...", isLoading = false }
    ↓
WeatherScreen → ErrorView 表示
```

## 10. メモアプリとの設計比較

| 項目 | メモアプリ | 天気アプリ |
|---|---|---|
| データソース | Room（ローカルDB） | Retrofit（外部API） |
| データ取得方法 | Flow（リアルタイム監視） | suspend fun（1回取得） |
| エラー処理 | ほぼ不要 | 必須（try-catch） |
| 結果の型 | List\<Note\> | sealed class（Success/Error） |
| APIキー管理 | 不要 | local.properties |
| 画像読み込み | なし | Coil（非同期） |

## 11. 将来拡張を見据えた設計ポイント

- `WeatherRepository` にインターフェースを導入することでテスト時のモック差し替えが容易
- `WeatherResult` を sealed class にすることで将来の状態追加（Loading など）に対応しやすい
- `WeatherResponse.toUiModel()` を分離することでAPIの変更がUIに影響しない
- `RetrofitClient` をシングルトンにすることで将来の複数API対応も容易
