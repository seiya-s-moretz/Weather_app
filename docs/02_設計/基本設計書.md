# 基本設計書（天気アプリ）

## 1. 画面構成

### 1.1 画面一覧
本アプリは単一画面で構成される。

| 画面名 | 役割 |
|--------|------|
| メイン画面（WeatherScreen） | 都市名入力・天気情報表示・エラー表示 |

---

## 2. メイン画面 UI構成

```
Scaffold
├─ TopBar（タイトル：「天気アプリ」）
└─ Content（Column）
      ├─ SearchArea
      │    ├─ TextField（都市名入力）
      │    └─ Button（検索）
      └─ ResultArea
           ├─ [通信中]    CircularProgressIndicator
           ├─ [取得成功]  WeatherCard
           │               ├─ 都市名
           │               ├─ 天気アイコン（Coil）
           │               ├─ 天気の説明
           │               ├─ 気温
           │               ├─ 体感温度
           │               ├─ 湿度
           │               └─ 風速
           └─ [取得失敗]  ErrorView（エラーメッセージ）
```

### 2.1 各UI要素の説明

| UI要素 | 説明 |
|--------|------|
| TopBar | 「天気アプリ」タイトルを表示する（CenterAlignedTopAppBar） |
| TextField | 都市名を英語で入力する |
| 検索ボタン | 天気情報を取得する。通信中は無効化 |
| CircularProgressIndicator | 通信中に表示するローディングUI |
| WeatherCard | 取得成功時に天気情報をカード形式で表示 |
| ErrorView | 取得失敗時にエラーメッセージを表示 |

---

## 3. 状態設計（UiState設計）

### 3.1 WeatherUiState

| 状態名 | 型 | 初期値 | 説明 |
|--------|----|--------|------|
| query | String | "" | 入力中の都市名 |
| isLoading | Boolean | false | 通信中フラグ |
| weather | WeatherUiModel? | null | 取得した天気情報 |
| errorMessage | String? | null | エラーメッセージ |

### 3.2 状態遷移

```
初期状態
  query = "", isLoading = false, weather = null, errorMessage = null

検索ボタンタップ
  → isLoading = true, weather = null, errorMessage = null

取得成功
  → isLoading = false, weather = WeatherUiModel(...), errorMessage = null

取得失敗
  → isLoading = false, weather = null, errorMessage = "エラーメッセージ"
```

## 5. コンポーネント構成（関数分割）

```
WeatherContainer          // ViewModelとUIの橋渡し
└─ WeatherScreen          // 画面全体
      ├─ SearchArea        // 入力欄 + 検索ボタン
      ├─ WeatherCard       // 天気情報カード
      └─ ErrorView         // エラー表示
```

### 5.1 各コンポーネントの責務

| コンポーネント | 責務 |
|----------------|------|
| WeatherContainer | ViewModelを取得し、状態・イベントをWeatherScreenに橋渡し |
| WeatherScreen | 画面全体のUIを描画。状態管理は行わない |
| SearchArea | TextField と 検索ボタンを表示する |
| WeatherCard | 天気情報を表示する |
| ErrorView | エラーメッセージを表示する |

## 6. データモデル設計

### 6.1 WeatherUiModel（UI表示用）

```kotlin
data class WeatherUiModel(
    val cityName: String,
    val description: String,
    val iconUrl: String,
    val temperature: Double,
    val feelsLike: Double,
    val humidity: Int,
    val windSpeed: Double
)
```

### 6.2 APIレスポンスモデル（Gson用）

```kotlin
data class WeatherResponse(
    val name: String,           // 都市名
    val weather: List<Weather>, // 天気情報リスト
    val main: Main,             // 気温・湿度
    val wind: Wind              // 風速
)

data class Weather(
    val description: String,    // 天気の説明
    val icon: String            // アイコンコード
)

data class Main(
    val temp: Double,           // 気温
    val feels_like: Double,     // 体感温度
    val humidity: Int           // 湿度
)

data class Wind(
    val speed: Double           // 風速
)
```

### 6.3 Result型（エラーハンドリング）

```kotlin
sealed class WeatherResult {
    data class Success(val data: WeatherUiModel) : WeatherResult()
    data class Error(val message: String) : WeatherResult()
}
```

## 7. アーキテクチャ構成

### 7.1 レイヤー構成

```
┌─────────────────────────────────┐
│  UI Layer                        │
│  WeatherScreen / Components      │
├─────────────────────────────────┤
│  ViewModel Layer                 │
│  WeatherViewModel                │
├─────────────────────────────────┤
│  Repository Layer                │
│  WeatherRepository               │
├─────────────────────────────────┤
│  Data Layer                      │
│  WeatherApiService（Retrofit）   │
│  WeatherResponse（レスポンスモデル）│
└─────────────────────────────────┘
```

### 7.2 メモアプリとの比較

| 項目 | メモアプリ | 天気アプリ |
|---|---|---|
| データソース | Room（ローカルDB） | Retrofit（外部API） |
| データ取得 | Flow（リアルタイム監視） | suspend fun（1回取得） |
| エラー処理 | ほぼ不要 | 必須（ネットワーク・404など） |
| Repository の役割 | DAOを抽象化 | APIを抽象化 |

## 8. 通信設計

### 8.1 Retrofit 設定

| 項目 | 値 |
|---|---|
| ベースURL | `https://api.openweathermap.org/` |
| タイムアウト | 10秒 |
| コンバーター | Gson |

### 8.2 APIエンドポイント

| メソッド | パス | 説明 |
|---|---|---|
| GET | `data/2.5/weather` | 現在の天気を取得 |

### 8.3 エラーハンドリング方針

| エラー | 原因 | 対応 |
|---|---|---|
| HttpException（404） | 都市が見つからない | 「都市が見つかりませんでした」 |
| IOException | ネットワーク未接続 | 「ネットワークに接続できません」 |
| SocketTimeoutException | タイムアウト | 「通信がタイムアウトしました」 |
| その他 | 不明なエラー | 「エラーが発生しました」 |

## 10. 今後の拡張を見据えた設計ポイント
- Repository にインターフェースを導入することでテスト時のモック差し替えが容易
- `WeatherResult` を sealed class にすることで将来のエラー種別追加に対応しやすい
- `WeatherUiModel` と `WeatherResponse` を分離することでAPIの変更がUIに影響しない
